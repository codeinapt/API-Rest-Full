## SPEC notes
- RC-01 covers the 3–100 length and the required name. The uniqueness half (`CATEGORY_NAME_ALREADY_EXISTS`) needs repository data, so it belongs to the T-11 handler.
- RC-02 throws `REFERENCED_AREA_INVALID` with `area.Id`, which matches docs/ai/09 (`REFERENCED_*_INVALID` takes `id`). The "area does not exist" case is left to the T-11 handler, as approved.
- RC-03 throws `CATEGORY_HAS_ACTIVE_PRODUCTS` with no arguments.
- RC-04 throws `CATEGORY_INACTIVE` with `Id` from both `Update` and `Deactivate`, in line with docs/ai/09 and DOMAIN_LOGIC §175–177.

## Evaluation of the implementer's choices
- **`Create(Area, name, createdAt)` and `Update(Area, name, updatedAt)` (human-approved):** acceptable. They follow Clean Code rule 7 and docs/ai/03.
- **`Deactivate(int activeProductCount)`:** acceptable. It mirrors `Area.Deactivate(activeCategoryCount)` from T-07.
- **Reflection helper `PersistedIdentity` in the test project:** acceptable. It is test-only, stays inside the task scope, and simulates the Id that Dapper assigns.
- **Check order:** `Update` checks the active state, then the name, then the area, and mutates only after all checks pass. The tests confirm that state is kept after a failure.

## Observations (not checklist failures)
- `EnsureValidName` reads `name.Length` before `string.IsNullOrWhiteSpace`. A `null` name would raise `NullReferenceException` instead of `VALIDATION_ERROR`. The T-11 validator should reject null first, or the order could be swapped later.
