   - the three `ErrorMessages` constants
   - `IProductWriteRepository.GetStockSnapshotAsync`
   - DI registrations in `Infrastructure/DependencyInjection.cs` and `Api/Program.cs`

2. `GetStockSnapshotAsync` reads the full `Product` row without a lock. SEQ-04 names a narrower `SELECT Id, Stock, IsActive`. This is the user's decision, and the conditional `ApplyDelta` preserves atomicity.
3. `ApplyDeltaSql` does not touch `UpdatedAt`, and it outputs only `deleted.Stock`. SEQ-04 also lists `inserted.Stock`, but `RecordStockChange` recomputes `ResultingStock`. Both follow the user's decisions and docs/ai/03.
4. The handler does not roll back explicitly. An unhandled exception leaves the transaction uncommitted, and `UnitOfWork.DisposeAsync` disposes it, which rolls it back. This relies on the same pattern as earlier tasks.
5. The new SQL was smoke-tested by hand against the compose SQL Server inside a rolled-back transaction (`sqlcmd -I`): an applied delta returns `deleted.Stock`, an insufficient one affects 0 rows, and the movement INSERT passes every CHECK.
