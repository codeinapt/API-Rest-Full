## Notes (non-blocking)
1. The `Merge coverage report`, `Publish coverage summary` and `Upload` steps use `if: ${{ !cancelled() }}`. The report and artifact are therefore still published when a test fails, but the gate step runs only after a green test step.
2. The gate step relies on `jq` and `awk`, which ubuntu-latest ships. The action tags (`@v5`) are floating major versions. Pinning to a commit SHA would be a later hardening, not a checklist item.
3. `MINIMUM_LINE_COVERAGE` lives in the workflow file. This is acceptable for CI configuration and contains no secret.
4. The `Measure Domain and Application coverage` step has no `if: !cancelled()`, so a failed test step skips the gate. That is the intended behavior.
